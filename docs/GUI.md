# GUI 设计（写作与发布工作台）

> 状态：设计稿，待确认后实现。目标不是"再做一个 CMS"，而是把现在 CLI 的写作链路
> （新建 → 写 → 校验 → 预览 → 构建 → 发布）变成可点、可看的工作台。

## 1. 定位与用户

| 项 | 结论 |
|---|---|
| 用户 | 作者（写稿、预览）+ 管理员（审核、构建、发布） |
| 形态 | **本地 Web GUI**：`python engine/gui.py` → 浏览器打开 `127.0.0.1:8788` |
| 不做的 | 在线多用户、数据库、富文本 WYSIWYG、图片云端存储 |
| 为什么不用 Electron/Tauri | 现有引擎是 Python，本地 HTTP + 浏览器零额外依赖、跨平台、体积小 |

## 2. 界面骨架

```
┌──────────────────────────────────────────────────────────────────────┐
│ Rust嵌入式探讨  │ 契约 ✓ 构建 ✓ 预览 ✓ │ [构建] [预览] [发布] │ 设置 │
├──────────────┬────────────────────────────────┬──────────────────────┤
│ 内容树        │ 编辑器                          │ 预览 / 检查器         │
│              │                                │                      │
│ ▾ 文章 2026  │  ┌ front matter 表单 ─────────┐ │  ┌ 实时预览 ────────┐ │
│   从零点亮…  │  │ title / author / date /    │ │  │ （渲染后的正文）  │ │
│   投稿其实…  │  │ tags / summary / map …     │ │  └──────────────────┘ │
│ ▾ 词条       │  └────────────────────────────┘ │  ┌ 检查器 ──────────┐ │
│ ▾ 成员       │  ┌ Markdown / SML 正文 ───────┐ │  │ 契约错误 / 字数   │ │
│ ▾ 项目       │  │                            │ │  │ 目录 / 附件 / 图  │ │
│              │  │                            │ │  └──────────────────┘ │
├──────────────┴────────────────────────────────┴──────────────────────┤
│ 路径 content/posts/2026/x/index.md │ 1,234 字 │ 已保存 │ 日志 ▸        │
└──────────────────────────────────────────────────────────────────────┘
```

- 左：`site/content` 树，按类型/年份分组；支持搜索、新建、草稿标记。
- 中：front matter 表单 + 正文编辑器（Markdown 默认；SML 切纯文本）。
- 右：实时预览（复用 `render`/`markdown`，与线上同源）+ 检查器（契约、目录、附件、图片尺寸）。
- 顶：状态点（契约/构建/预览）+ 三个动作；底：路径、字数、保存状态、日志抽屉。

## 3. 功能分期

### M1（先把闭环跑通）
- 内容树浏览 + 搜索
- 打开/编辑/保存（**强制 UTF-8 无 BOM**，保存前自动校验）
- front matter 表单（字段来自 `contracts/blog.sml`，类型/必填/枚举驱动）
- 实时预览（服务端渲染，和构建同源）
- 契约错误定位到字段/行
- 新建文章（复用 `cli.py new` 的模板）

### M2（写稿顺手）
- 图片拖入 `assets/`，自动生成 Markdown/SML 片段（复用 `cli.py assets` 的尺寸检测）
- 附件表单（名称/渠道/URL，自动识别蓝奏云等）
- 目录/字数/阅读时长
- 草稿开关（`draft: true`）
- 代码块/表格/公式插入按钮（公式走已有的 `$...$`/`$$...$$`）

### M3（发布与 AI）
- 「生成摘要」：调 `ai_summarize`（网关环境变量），展示 JSON，可手改后落盘 `summaries/<slug>.json`
- 「构建」：跑 `build + check + test_structure`，日志实时输出
- 「发布」：`git add/commit/push`（提交信息可编辑，**永不 force**；推 Gitee）
- 发布前检查清单：契约通过、构建通过、附件链接可达

### M4（进阶，可选）
- SML 结构化块编辑（表单化 `:::panel` 等）
- 内容模板/片段库
- 多语言/多站点切换

## 4. 技术方案

```
engine/gui.py            # stdlib http.server，127.0.0.1:8788
engine/gui_web/          # 静态 index.html + app.js + style.css（零构建）
engine/gui_api.py        # API 路由，直接调用 engine 现有库
```

API（全部本地、JSON）：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/tree` | 内容树（类型/年份/标题/草稿） |
| GET | `/api/doc?path=` | 读文件（返回 front matter + body） |
| PUT | `/api/doc` | 保存（UTF-8 无 BOM，先校验契约） |
| POST | `/api/validate` | 只校验，返回错误列表 |
| POST | `/api/preview` | 渲染正文为 HTML |
| POST | `/api/new` | 新建（等价 `cli.py new`） |
| POST | `/api/asset` | 保存上传图片到 `assets/`，返回片段 |
| POST | `/api/ai-summary` | 调网关生成摘要（可选，失败不阻断） |
| POST | `/api/build` | 构建 + 自检，返回日志 |
| POST | `/api/publish` | git add/commit/push（需确认） |

复用而不是重写：`build.py` 的加载/渲染、`lib/contract.py` 的校验、`lib/markdown.py`、
`lib/render.py`、`ai_summarize.py` 的网关调用、`cli.py` 的模板与图片尺寸逻辑。

## 5. 安全与纪律

- 只监听 `127.0.0.1`，不提供公网入口；
- 写操作（保存/发布）需要显式点击，发布前展示 diff stat；
- **永不 `git push --force`**；Gitee token 走环境变量或 git 凭证，不落仓库；
- 上传只允许图片类型 + 大小上限（与站点附件规则一致：2 MB / 20 张）；
- 保存时统一：UTF-8 无 BOM、LF、末尾换行（避免 CI 的 builtin SML 解析失败）。

## 6. 验收标准

- GUI 内完成「新建 → 写 → 预览 → 校验 → 构建 → 发布」，产物与 CLI 完全一致；
- 保存后的文件能直接过 `engine/cli.py build` 与 `test_structure.py`；
- 断网时除「AI 摘要/发布」外全部可用；
- 不引入新的运行时依赖（Python 3.11+ 标准库）。
