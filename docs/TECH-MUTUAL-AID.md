# 技术互助：定位、文案与字段

> 决定（2026-10-19）：导航名 **技术互助**；**能力图谱放主页**，不单独占导航；
> 页面两栏 **能帮上什么 / 想一起做什么**；`rate` 字段保留，但只写**协作方式，不谈价格**。

## 1. 信息架构

```
主页
└─ 能力图谱（技能聚合 + 成员入口）  ← 总览，不占导航
技术互助（导航）                    ← 明细：能帮上什么 / 想一起做什么
└─ 条目详情：能帮上什么 / 想一起做什么 / 协作方式 / 联系
```

- 路由仍保持 `#/services`、`#/service/<id>`，只改可见文案，避免旧链接失效；
- 主页「能力图谱」由现有 `services.skills` + 成员数据聚合，不新增字段；
- 没有 service 条目时，主页整块隐藏（不显示空标题）。

## 3. 页面文案

导航：**技术互助**

页面标题：

```text
技术互助
这里只做技术互助与能力互补，不涉及设备买卖、报价与商务对接。
```

列表卡片固定四段：

```text
能帮上什么     skills
想一起做什么   wants
协作方式       rate（远程 / 线下 / 开源 / 志愿 / 一起做项目；不写价格）
怎么联系       contact（只引用成员已公开的 links）
```

详情页分区：

```text
## 能帮上什么
## 想一起做什么
## 协作方式（不谈价格）
## 怎么联系
```

条目底部固定一句：

```text
本站只展示这条信息：不参与交易、不担保结果、不抽成、不经手资金、不介入纠纷。
```

## 4. 主页「能力图谱」

标题与说明：

```text
能力图谱
群里能帮上忙的方向，按技能聚合；点技能看对应成员与互助条目。
```

展示：

- 技能 chip + 出现次数（取 `services.skills` 的并集，按次数排序，最多 12 个）；
- 右侧/下方：`看技术互助 →`，链到 `#/services`；
- 不画复杂 SVG 图；先用 chip 网格，避免为了“图谱”造一个难维护的图；
- 条目为空时整块隐藏。

## 5. 字段语义（保持兼容）

```sml
@contract Service {
  ...
  rate: str optional   # 协作方式（远程/线下/开源/志愿/一起做项目）；不写价格、不写报价
  status: enum [ active paused ]  # UI 显示「可协作 / 暂缓」
}
```

- 字段名 `rate` **不改**，避免契约与现有内容破坏性变更；
- UI 标签从「费用 / 方式」改为「协作方式」；
- 不在站内出现价格、报价、抽成、支付方式；
- 现有示例 `pcb-emc-review.sml` 的 `rate` 需要从「按板计费，学生项目半价…」改为协作方式描述；
- `wants` 里避免「接单/外包/报价」，改成「一起做/交流/共建」。

## 6. 暂不做

- 不做“找人/找活”招聘语义；
- 不做整群接项目/派单/合同/资金；
- 不做成员简历 PDF（作品集聚合先做站内页面，PDF 以后再说）。
