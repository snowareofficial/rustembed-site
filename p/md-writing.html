为什么不用逼你学 SML

站点底层是 SML，但投稿不要求写 SML：posts/<年份>/<短名>/index.md 走 Markdown， index.sml 走 SML，两者渲染出来的样式、章节树、搜索索引完全一样。

需要 SML 的场景只有两种：想要严格契约校验（@contract 钉字段类型），或者要写定理/证明这类结构化内容。

文件长什么样

目录结构就两个文件的事：

text
posts/2026/md-writing/
├─ index.md          ← 正文 + front matter
└─ assets/           ← 图片放这里（可不存在）

front matter 只要 5 个必填字段：

字段说明
title标题
author成员 id（对应 members/<id>.sml，没有档案也能发，只是不会链接到个人页）
date发布日期 YYYY-MM-DD
tags标签数组，如 [ rust embedded ]
summary一两句摘要，列表页与分享卡片用

正文能写什么

标题、段落、粗体、斜体、删除线、行内代码、链接、 列表、表格、引用、围栏代码块、图片，都支持。

rust
#[entry]
fn main() -> ! {
    let dp = pac::Peripherals::take().unwrap();
    loop { cortex_m::asm::wfi(); }
}

引用也可以嵌套列表和代码。

单独一行放 B 站视频号就会自动嵌入：

▶在 B 站观看 BV1GJ411x7h7（点击加载播放器）

图片放同目录 assets/，正文里写相对路径 ![说明](assets/xxx.png)，可加 "图注"：

text
![接线图](assets/wiring.png "USART1 接线")

构建会检查这类本地图片是否真的存在，路径写错会直接报错。

附件

图片入库；PDF / 压缩包 / 固件一律走外链，写在 front matter 里：

yaml
attachments:
  - name: 示例工程
    kind: link
    url: https://gitee.com/rustembed/site
    size: 1.2 MB

最后

提 PR，或者把稿子丢给有仓库权限的群管理代投。格式问题构建脚本会直接报出来，不用你自己猜。
