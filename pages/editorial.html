投稿流程与时限

  1. 作者新建 site/content/posts/<年份>/[系列/]<英文短名>/index.md（也可用 .sml），本地跑一遍 python engine/cli.py build 与 check；
  2. 提 PR（或在群里把稿子发给管理员代投，署名归作者）；
  3. 自动检查 + 管理员审阅：3 个工作日内给出结论；
  4. 通过即合并，下一次构建后上线；需要修改会写明原因与建议。

超时未回复可在群里 @ 任意管理员催办。没有回复不等于通过，不要自行合并。

审稿标准（按顺序看）

维度要求
事实命令、参数、代码能跑通；版本、平台、型号写清楚
可读有摘要与章节结构，长文有小标题；不堆砌无关输出
合规引用标出处；不含未授权转载与内部资料；截图抹掉密钥与个人信息
附件图片入库、其它走外链，符合「附件规则」
格式字段按契约填全（构建会自动校验，报错带 E-CONTRACT-xxx 与人话说明）

署名、版权与许可

  • 署名默认写 author: <成员 id>；多人合作用 co_authors；
  • 默认许可 CC BY-NC-SA 4.0，可在文章里用 license 字段覆盖；商用需作者另行授权；
  • 翻译与转载他人内容必须标注来源与原作者，并确认对方许可；
  • 代投不改变作者身份与版权归属。

退稿与修改

退稿会写明原因（事实错误 / 格式 / 许可 / 附件问题），可按意见修改后重提。 同一作者连续两篇因同类问题被退，管理员会在群里说明规则要点，避免反复返工。

更新与纠错

  • 已上线文章发现错误：任何人均可提 PR 修正；文章会显示更新日期；
  • 重大修订（结论变化、删改大段）需要原作者知情，管理员在 PR 里 @ 作者；
  • 作者本人可随时要求更新或下架自己的文章。

内容边界

  • 只谈技术与学习；不做商业推广（内推走「加入我们」页）；
  • 不涉及违反法律法规、侵犯他人权益、危害他人的内容；
  • 立场性争论不进入站点正文；可以写技术取舍，但不做人身评价。

纠纷与异议

对审稿结论有异议，可在群里提出，管理员必须给出书面理由； 涉及下架与申诉的，按「下架与申诉制度」处理。
