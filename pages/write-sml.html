什么时候值得用

Markdown 够用的场合就用 Markdown。下面这些情况 SML 更顺手：

  • 需要严格字段校验（错字段名会直接报错，而不是被静默忽略）
  • 要写定理 / 证明 / 公式这类结构化内容
  • 同一段内容要在多处复用（片段 &引用）
  • 希望正文与元数据在同一个文件里都是结构化数据

让人觉得舒服的四个点

多行文本直接写

引号里的换行就是换行，不用 转义。段落里想怎么写就怎么写—— 第二行照样是同一段文字，缩进也不影响解析（SML 不依赖缩进定界）。 空行也在字符串里原样保留。

裸词即字符串

中文、邮箱、路径都不用加引号，只有含空格或特殊符号时才需要。

sml
state: NY
to: a@b.c
path: /api/v1/health
contain_space: "才需要引号"
含中文的裸词: 也可以

块冒号可省

address { } 与 address: { } 等价；数组里逗号可选、可换行、可混着写。

sml
server {
  host: db1.internal
  port: 5432
}

tags: [ urgent internal q3 ]
ports: [ 80, 443, 8080 ]

片段复用

把重复的部分定义成 @名字，用 &名字 以值的形式引用。本站的成员档案就是这么写的。

sml
@链接 {
  repo: "https://gitee.com/rustembed/site"
  sml: "https://sml.swebase.cn"
}

档案 {
  name: Sal
  links: &链接
}
